监控店铺"瑾漂亮潮流服饰"的推广数据，两项能力均只覆盖**乘方**（全店托管 + 商品自选）：
- **自动暂停**：当天累计推广费用整数分 > 当天累计全店订单数 × 100 时自动暂停乘方（08:00 后每 30 分钟巡查）。
- **每日自动开启**：每天上海时间 07:00 开启**当前全部**乘方计划（全店托管 + 商品自选，含昨日被暂停的全部计划，而非仅系统记录）。

默认**演练模式**（只记录不点击），真实执行开关默认全部关闭（`realMode=false`、`pauseEnabled=false`、`enableEnabled=false`）。

入口区分（读取 / 演练 / 真实执行）：
- **读取**：`orders` / `ads` / `chengfang-read` —— 只读，不打开任何可点击路径。
- **演练**：`chengfang`（dryRun 恒 true，无视 pauseEnabled）与 `poll`。演练入口（`runDryCycle`）**无条件强制 dryRun:true**，即使配置已允许真实执行也零点击；身份/读取/分页/选择范围失败以 `dry_failed` 透出，不显示为"正常枚举"。
- **真实执行**：无 CLI 命令。真实暂停只能由监控主链路发出，且必须同时满足 `execution.realMode=true` 与 `monitor.chengfang.pauseEnabled=true`（以及每日 08:00 后 Asia/Shanghai、未停止、业务日期一致等门槛）；**单独改 pauseEnabled 不会生效**，显式 `dryRun:false` 也不能越过配置门槛。请求级门槛**每次点击都实时重算当前配置许可**：运行中关闭 pauseEnabled/realMode 立即生效；磁盘 config.json 的修改需重新 loadConfig（进程不宣称支持免重载热更新）。

## 乘方暂停流程（可审查，fail-closed）

1. 身份核验：URL/子标签/账户 ID 与配置精确比对，任一不一致 → 停止。
2. 全店托管：读取开关状态；已关闭 → 幂等跳过；开启 → 点击行内开关（严格单候选）→ 强制新扫描回读确认。
3. 商品自选：确保 100条/页（切换后等待加载）→ 以稳定 ID 为基准逐页处理：
   - 表头全选后**实测选择范围**（当前页 or 跨页，以"批量栏已选N个"与 DOM 选中集合交叉核对，不靠猜测）；
   - 多余选中精确取消勾选，仍不收敛 → 停止；批量栏计数与实际选中不一致 → 停止；
   - 每次决策前强制新扫描 + 危险弹窗检测（含删除确认，弹窗存在即停止，不点击通用"确定"）；
   - 精确定位唯一"暂停"按钮（带 `data-auto-id`/`data-e2e` 识别标记，禁止模糊文本/序号/坐标兜底；删除/开启绝不点击）；
   - 批量暂停后列表可能收缩（行消失/前移）：以稳定 ID 去重，翻页只在"当前页无未处理目标且还有下一页"时进行，避免页码位移漏处理；行消失不当作已关闭，记入全量回读核验。
4. 全量回读验证：两部分目标逐一确认开关=关闭侧；仍开启/行缺失 → 不报告"乘方全部已暂停"。
5. dryRun=true 时只枚举"将执行的动作"（不勾选、不点击任何开关/暂停）。

## 自动监控主链路（本轮接入）

`monitor.js` 每 30 分钟巡查（08:00 Asia/Shanghai 后）：读取费用/订单（身份/日期/时效/零订单重读核验）→ 仍严格超过 1 元/单 → **只走乘方主链路**（`ChengfangRunner`）：

1. 批次开始前重新读取费用与全店订单：仍超标才继续，否则取消（零请求、不打开页面）。
2. 集中门槛（`chengfang-gate.js`）：realMode=true + pauseEnabled=true + 非演练 + 上海 08:00 后 + 未停止 + 业务日期一致；**每个真正发出的**托管关闭/批量暂停请求前逐次复查，且**每次 check 实时重算当前配置许可**（不依赖批次最初缓存）。
3. 打开乘方页 → 执行器（身份核验 → 全店托管 → 商品自选 → 全量回读）→ 关闭会话 → 批次按 店铺+业务日期 持久化。
4. **贴近真正点击的最终检查（beforeDispatch）**：执行器注册回调到控制器，在每次实际业务点击派发前——最后一次异步页面检查（定位/弹窗检测）完成后——再次校验停止/时段/跨日/当前许可，并**复检账户/页面身份**；任一不满足即拦截点击（零点击停止），杜绝"只依赖批次最初身份核验"与"运行中撤许可仍放行"。身份复核为**双重门槛**：复核前检查一次 `requestGate`，身份复核成功返回后再**同步检查一次** `requestGate`（停止/跨日/许可可能在异步核验期间变化），不通过立即抛错禁止派发点击。

只控制乘方：配置了 `monitor.chengfang.scope` 时监控绝不进入历史"全店关闭"流程（该路径仅测试显式开启 `monitor.legacyWholeShopCloseEnabled=true` 才可达，生产配置不设置）；未配置乘方范围且未开启历史路径 → fail-closed 不执行任何关闭。

## 乘方自动开启流程（每日 07:00 相位，可审查，fail-closed）

每日上海时间 07:00（`monitor.chengfang.enableHour=7`）自动开启**当前全部**乘方计划（全店托管 + 商品自选，含昨日被暂停的全部计划，而非仅系统暂停记录）。**独立于费用/订单阈值**——开启相位不读取费用与订单，也不依赖暂停门禁：

- **独立门禁**：真实开启必须同时满足 `execution.realMode=true` 与 `monitor.chengfang.enableEnabled=true`（均默认 false）+ 上海时间在 `[enableHour, dailyStartHour)` 窗口内 + 未停止 + 触发业务日期一致；`enableEnabled=false` 或 `realMode=false` → 自动转演练（只枚举将开启目标，零点击）。请求级门槛每次点击实时重算当前配置许可（同暂停）。
- **调度**：`monitor.js` 开启窗口 `[07:00, 08:00)` 内每天执行一次（`_lastEnableDate` 跨日重置）；执行后等待到 08:00 进入暂停巡查；暂停巡查跨日时等待次日 07:00（而非直接跳 08:00），保证次日开启相位被唤醒。**监控未启动不自行执行任何开启/暂停**；无 CLI 真实开启入口。
- **范围与分页**：全店托管（行内开关，已开启幂等跳过）+ 商品自选（100条/页；超过 100 条严格分页、稳定 ID 去重、逐页完整性核验；同名不同 ID 精确区分；空页/跳回首页不当作成功）。
- **同会话单次重试**：千川首次批量开启有时确认成功却未落地（首次未确认）。本次浏览器会话内记录乘方管理页 URL（`result.managementUrl`，仅会话内使用，不写审计日志）；操作后回读仍关闭 → **同一 page/browser/context 内恢复该 URL 重试一次**（不重开浏览器、不重建上下文、不重读 Cookie）；第二次仍未确认 → 停止并标记结果未知。提交后跳回首页同样回到记录的乘方 URL 回读，恢复失败即结果未知。
- **操作前/后**：身份核验 → 每个真实点击前 `beforeDispatch` 双重门禁复查（含异步身份复核后同步再查）→ 操作后强制新扫描回读 → 全量回读（两区域完整当前清单，对象键=区域+稳定ID）确认全部开启侧才报告"乘方全部已开启"。
- **只点"开启"**：批量栏"开启 / 暂停 / 删除"并存时，只点击唯一、带稳定标识的"开启"按钮；删除按钮仅用于危险检测（点击次数恒为 0）；删除确认/非预期弹窗/按钮缺失或重复 → 零操作停止。

## 安全机制

- 防误删硬性约束：业务动作只允许 pause / enable，**不提供 delete 动作**；按钮缺失/重复/无标记 → 零点击停止。
- 弹窗检测失败 = 停止：`detectDanger` 异常直接抛出，执行器据此阻断后续点击（绝不当作无弹窗）。
- 读取失败 ≠ 已确认无计划：`read_failed`（不当作空/已关闭）与 `confirmed_empty`（成功读取且分页 total=0）严格区分；空清单缺分页字段不当作空。
- 点击结果未知（超时/断连）→ 强制回读实际状态，禁止盲点重试；托管开关是切换动作，回读仍开启时绝不再次点击（避免反向开启）。
- 全量回读 = 完整当前范围：从第一页起逐页扫描，核验分页总数与页码；对象键 = `区域:稳定ID`；新增/重新开启/状态未知/目标失踪/分页不完整 → 不报告"乘方全部已暂停"或"乘方全部已开启"。
- 跨页选择范围：优先清除跨页选择、按已核验的当前页目标重选；平台残留不可见跨页选择（范围无法确认）→ 停止，不宽松通过。
- 操作后强制新扫描：绝不复用操作前缓存；两部分均重新读取并确认关闭（或开启）后才报告"乘方全部已暂停"（或"乘方全部已开启"）。
- **落地确认（有界轮询，2026-09-16 统一）**：点击已派发后按**实际截止时间**等待平台异步落地（平台实测可延迟 27 秒以上），读取串行、绝不与上一轮重叠。唯一有效配置 = `execution.readbackTimeoutMs`（默认 30000）/ `execution.readbackIntervalMs`（默认 3000）；执行器与页面展示同源解析（`src/lib/bounded-poll.js`），**不存在独立的 fallback 数值**。旧实现按 `ceil(timeout/interval)` 计次数（未计入读取耗时）→ 慢读取让等待无限延长，已废弃。轮询一律使用**真实单调时钟**（业务时钟 `now` 是当次检查时刻的快照，只能用于上海时段/跨日判断）。注意：这两个键同时被**关闭推广流程**（`close-flow.js`）复用为单次读取超时与重试间隔，调大只会更耐心、不会更激进。
- **停止语义（2026-09-16 恢复）**：收到停止后立即禁止重试与任何新业务请求，但**已派发请求继续在有限期限内只读确认**（默认沿用原预算），并如实记录真实回读结果（`result.stoppedAfterDispatch`）；绝不因停止把已落地的动作谎报为失败。
- **同会话重试的前置核验（2026-09-16 补齐）**：仅在"首次未落地且状态明确"时才允许同会话重试一次；重试前必须**重新核验**停止/时段/跨日/配置门槛、页面身份与**真实开关状态**——若重试前发现已落地则不再重发，若目标行消失（状态未知）则不重发。
- **会话 Cookie 回写（2026-09-16 用户明确授权）**：操作完成、回读确认且身份核验通过后，在浏览器关闭前把本次 context 的 Cookie 回写到**本次实际加载的精确店铺 Cookie 文件**（`src/login/cookie-writeback.js`）。原子写入（临时文件 + fsync + rename）；登录失效/身份不符/空或非法 Cookie/缺少抖店与千川关键域/条数塌缩 → **拒绝覆盖**；会话期间源文件被改动（用户重新登录）→ 冲突保护，保留较新文件、不做无依据合并；写入后自校验不一致即原子回滚。回写失败**单独记录**，绝不改写已确认的广告动作结果；当前批次继续使用原 context，不回灌、不刷新会话；**绝不输出任何 Cookie 值**（返回与审计只有数量/域名/字节数）。
- 保留已有保护：停止信号、跨日等待、超时未知、重新核实费用与订单、回读不到≠成功、原子持久化、脱敏。
- 真实执行门禁（独立两套，均默认关闭）：真实暂停 = `execution.realMode=true` + `monitor.chengfang.pauseEnabled=true`；真实开启 = `execution.realMode=true` + `monitor.chengfang.enableEnabled=true`；无 CLI 真实执行入口。

## 推广值守（3443 页面）

> **历史标注（重要）**：下面 r11（2026-09-14）段落描述的「独立强制只读演练入口 / 不含任何广告操作代码路径」
> 是**当时**的语义。自 2026-09-15 起 3443「推广值守」已接入**真实操作模式**：是否真实操作广告由

> 阅读下方历史段落时按历史记录理解，不得以其覆盖当前语义。

**独立强制只读演练入口**（历史语义，r11，2026-09-14）：接入电商助手 3443 首页 Tab「推广值守」，当时只评估数据、不操作广告。

- **只读边界**：后端模块（`电商助手/bill-manager/watch-drill.js`）不含任何广告操作代码路径——不导入/不调用乘方执行器、广告控制器、开关、批量暂停、开启、删除。即使 `execution.realMode` 或 `monitor.chengfang.pauseEnabled` 被置为 true，本入口仍零广告操作（测试已覆盖双开关全开场景）。
- **数据与规则复用**：千川账户整体消耗（`qianchuan-reader.js`）+ 罗盘经营概况全店+实时订单（`compass-order-reader.js`）+ guard 校验链（身份/业务日期=当天/时效/同店同日）+ `evaluateWholeShopCostPerOrder`（整数分判定：费用分 > 订单数×100 才超标，恰好相等不超标）。不重新实现抓取。
- **后端调度**：上海时间 08:00 后启动立即读取一次，此后每 30 分钟巡查（`nextIntervalDelayMs` 跨日规则）；08:00 前等待到 08:00。调度在 3443 进程内，不依赖浏览器
    Tab；刷新/多 Tab 不重复启动也不停止值守；停止后不再安排下一轮；服务重启默认不自动恢复；页面加载不自动启动。**单一活跃读取守护**：每轮读取有独立超时（默认 120s）；新读取开始前必须先确认旧读取已结束或已取消释放，无法确认时本轮跳过并显示「等待旧读取结束」（仍安排下一轮）——不重叠浏览器任务、不堆积任务、不静默停机。
