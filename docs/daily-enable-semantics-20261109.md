# 每日自动开启语义（2026-11-09 定稿）

**本语义已经用户确认（2026-11-09）：每日 00:05 自动开启是设计行为，不再作为问题质疑。**

## 设计语义

- **每日 00:05（Asia/Shanghai）后首查**：独立任务（`_enableLoop`，与值守巡查相互独立——停止值守不取消本任务），检查各店**当天是否处于暂停状态**。
  - **暂停才作为当天首次开启对象**：昨日（或当日早些时候）被费比规则暂停的店，在次日 00:05 首查时自动开启当前全部乘方计划（全店托管 + 商品自选）。
  - **已开启的店零点击记完成**（already_on）：不重复开启、不重复点击。
- **当日未完成时有界重试**：5 分钟间隔（`ENABLE_RETRY_MS`），当日有效。
- **服务中途启动补跑**：进程在当日任意时刻启动（或重启）时，若当日开启检查未完成，登记后补跑（服务启动顺序=先启动费比巡查，再登记每日开启，避免抢锁）。
- **费比巡查的对称行为**（与每日开启独立、随 30 分钟巡查周期）：当天费用整数分 **严格大于** 订单数 × 阈值 → 当轮立即暂停（无时段门/首查门）；费比回落到阈值内且当前 off → 当轮决策 should_enable 重开。费比在阈值附近波动时会出现"暂停→重开"来回切换，属规则对称行为。
- 真实执行仍受三重门（`realMode` + `enableEnabled`/`pauseEnabled` + 非 dryRun），登录失效/数据无效一律 fail-closed 零点击。

## 相关配置

- 阈值按店配置（`shops[].thresholdCents`，单位=分/单）；判定用整数分严格大于，恰好相等不触发。
- 0 单、数据读取失败、广告状态未知：**不暂停、不误关**（数据有效性原则）。
