# D51 prior-day zero-consumption recovery and ongoing automatic refill

The current-day first ledger slot can be unknown/read-only-recovery-required without a runId or startedAt while the publisher still holds the previous day's safely closed preparation. The new narrow recoverShopDay branch re-proves that original prior-day closure, independently verifies that no current/future consumption or publication exists, and re-arms only this first current-day slot. The prior-day proof keeps its actual date/runId; no success or planId is invented. A successful local recovery changes only the target ledger record and keeps publisher files unchanged. A history event preserves provenance when the normal scheduler replaces the pending entry.

The branch accepts only the precise first-slot record, trusted identity and strict six-zero durable closure. Optional native final/reopen tables are handled without fabricating them; malformed tables and current/future or undated facts refuse. CAS starts before reading any proof surface and is checked against the old-day reproof, before locking and under the scheduler lock. Marker-only idempotence requires a consistent pending-zero record, proof/history, account and unchanged source bytes. Existing crash/F1/R16 code bodies are unchanged.
